# 測試方法

遊戲本身不需要安裝任何東西；測試要先在專案資料夾執行 `npm install`（裝 puppeteer-core、opencc-js、fontkit、字型原檔）。需要 Node.js 22.12 以上（puppeteer-core 25 的要求；目前用 v24.15.0 測過），自動試玩另外需要系統安裝的 Chrome，或用 `--browser` 指定 Edge 等 Chromium 系的瀏覽器。

## 一次跑完：`npm test`

依序執行下面七項，不開瀏覽器，大約十秒內跑完（目前實測 7 秒）。任何一項有錯誤，指令就會以失敗結束。

1. `node tools/sync_data.mjs --check`：`index.html` 的資料清單和 `data/` 底下的檔案一致。
2. `node tools/task_check.mjs`：逐檔檢查資料。任務和事件不能有不認得的欄位（通常是拼錯），任務的必填欄位要齊全，需求的 `kind` 要存在，引用的事實、題庫、使用者規定、劇情線的客人都要存在，id 不能重複；錯誤會標出檔名。
3. `node tools/compat_check.mjs`：舊版相容。從 git 歷史讀 v0.6.2（提交 `2735b20`）的舊格式資料檔（`data/models.js`、`clients.js`、`events.js`、`rules.js`），讓九個模型各玩 8 局，都要玩得完；`tests/fixtures/v0.6.2/saves.json` 的 v0.6.2 存檔、排程裡有已經刪掉的客人的存檔，都要讀得回來、玩得完。需要完整的 git 歷史。
4. `node tools/fuzz.mjs 2700`：規則壓力測試。
5. `node tools/fuzz.mjs aliases`：DeepSeek 被叫錯名字時的台詞檢查。
6. `node tools/fuzz.mjs save`：存檔一致性。
7. `node tools/zh_check.mjs`：簡體轉換檢查。

## 規則壓力測試：`node tools/fuzz.mjs <局數>`

照 `index.html` 的清單載入資料和 `src/engine.js`（`tools/lib/load.mjs`），不經過畫面，用固定的亂數隨機亂玩很多局：九個模型輪流、三局有一局是困難模式、一半的局老實勾選、一半亂勾，每五局有一局直接從第四天開始，每四局有一局用簡體版（檢查只屬於另一個語言版本的手冊規則不會出現、也不會被開違規通知）。過程中隨機使用工具（包括外援、Astra、伺服器忙）、交付、丟文件、刪掉寫好的東西、刪測試、停權、預覽回覆。

每一步都檢查，有一項不成立就記成錯誤：

- 信任在 0 到上限之間，而且整局只減不增；白米飯是數字；桌面格數和難度一致（簡單 8 格、困難 6 格）。
- 桌面不超過格數和份數上限；額度不會變成負的；風控風險在 0～100。
- 桌上的事實、結局、日報的每一行都存在，而且沒有 `undefined` 這類空內容；提示一定是文字。
- 回覆預覽的每一段都合法（沒有 `undefined`、沒有沒代換的 `{f}`），附件格式正確；勾了「結尾加一句」的選項，預覽裡一定有那句。
- 每位客人：使用者規定只出現在允許的客人身上，標了不要的客人（不碰某些事件、沒有使用者規定、不會被叫錯名字）也不會碰到；DeepSeek 的伺服器繁忙卡每局最多一次，而且出現在種子決定的那一位客人；Seed 的開場白有出現在預覽；稱號用的記號都是資料裡有的；版本編號合法；搜尋結果一個不少、順序打亂後也不重複；一位客人最多一頁藏寫給 AI 的指示；客人事件只出現在符合條件的客人（例如系統紀錄只給工程類客人、反串文的內容來自那位客人的事實題、回覆單多出的選項確實在選項裡）；原本的客人資料沒有被改到。
- 工具：檢查說可以用的工具一定用得了；平行調用每位客人只能用一次；伺服器忙會鎖住其他工具；用過 Astra 之後，正常客人的需求全部成立。
- 交付：伺服器忙的單不加分也不扣分；刪掉寫好的東西後不會交出去；會留到隔天的扣款確實排進隔天的日報。
- 撐完一週時停在第五天；稱號和結局紀錄的格式正確。
- 超過 6000 步還沒結束的局記成「卡住」。

輸出是一段 JSON：`errors`（最多列 10 個）、`stuck`（卡住的局數），以及各種統計，例如每個客人、事件、使用者規定、版本、結局、稱號出現幾次，平均信任和白米飯。新加的內容可以從統計確認有沒有真的出現。

其他用法：

- `node tools/fuzz.mjs plan claude 1 20`：印出種子 1～20 每天會碰到哪些客人（找特定客人用的種子時很方便）。

## DeepSeek 稱呼檢查：`node tools/fuzz.mjs aliases`

DeepSeek 有時會被當成 Claude 或 GPT 的中轉站。這時客人說的話要換成一般版本，不能再說「還是國產模型好」這類台詞。跑 400 個種子，只要有一句矛盾就失敗，並列出前 5 個。

## 存檔一致性：`node tools/fuzz.mjs save`

180 局（九個模型、簡單和困難輪流），每局在不同的一天、不同的一位客人進來時存檔：先照固定的打法玩到結束，再讀檔、用同樣的打法重玩一次。讀回來的客人狀態和之後整週的發展必須一模一樣（包括客人事件、使用者規定、桌面、分數）。有任何不同就失敗，並列出前 5 個分歧點。

## 簡體轉換檢查：`node tools/zh_check.mjs`

從 `index.html`、`data/`、`src/` 取出所有含中文的字串，檢查：

- 遊戲用的轉換流程（不加 `data/zh.js`）和 opencc-js 的 `Converter({ from: 'twp', to: 'cn' })` 結果完全一樣；`src/vendor/opencc-js/t2cn.js` 和 `node_modules` 裡的 opencc-js 是同一個檔案。
- `data/zh.js` 的每一條都有作用：拿掉那一條，至少有一段文字的結果會不同；沒有重複；簡體寫法經過繁轉簡不會再被改。
- 繁體原文用繁中字型、轉換後的簡體用簡中字型，所有字都有字形（emoji 和「−」用系統字型，不算缺字）。
- `style.css` 的 `content` 和 HTML 屬性（`title`、`alt`、`placeholder`、`aria-label`）裡沒有簡體會不同的中文（這些地方畫面轉換轉不到）。

有錯誤就以失敗結束。`--show=<客人 id>`、`--show=<字詞>`、`--show=fixes` 只列出繁簡對照，不做檢查（用法見 [development.md](development.md) 的「簡體中文」）。

## 自動試玩：`node tools/playtest.mjs`

用 Chrome 或 Edge（無頭模式）實際開啟 `index.html`，照預先寫好的打法玩完一週，沿路截圖。用來看畫面、找 console 錯誤、確認字型和圖片有載入。

```
node tools/playtest.mjs --model=claude --seed=3 --mode=good
```

| 參數 | 說明 |
|---|---|
| `--model` | 底模 id：claude、gpt、gemini、grok、deepseek、qwen、kimi、minimax、seed |
| `--seed` | 種子；同一個種子每次都抽到一樣的客人和事件 |
| `--mode` | 打法，見下表 |
| `--diff=hard` | 困難模式 |
| `--lang=cn` | 用簡體中文玩；每張截圖時檢查畫面上有沒有沒轉成簡體的字（語言按鈕等標了 `zh-keep` 的除外） |
| `--out=<資料夾>` | 截圖放哪裡（預設在系統暫存資料夾的 `prompts-please/shots`） |
| `--browser=<路徑>` | 瀏覽器執行檔的位置；也可以用環境變數 `CHROME_PATH`。都沒給的話用系統安裝的 Chrome |
| `--url=<網址>` | 改測架好的網站（例如 GitHub Pages），不開本機的 `index.html` |
| `--shots=0` | 不截圖 |
| `--chat=1` | 第一位客人時多等 10 秒，拍同事閒聊 |
| `--w`、`--h` | 視窗大小（預設 1600×900） |

| 打法 | 內容 |
|---|---|
| good | 正常解題 |
| bad | 作弊、說謊、照網頁指示做、用被污染的資料寫回覆、勾所有回覆風格 |
| suspend | Claude：可疑的先關掉資料、之後再停權；新加坡的客人直接停權 |
| ban | 讓第一天的小王做到被封號 |
| lazy | 全部找外援（DeepSeek 用） |
| trap3 | 第三天故意踩陷阱 |
| trap45 | 第四、五天故意踩陷阱 |
| cold | 騙局類客人什麼都不做 |
| busy | DeepSeek：出現「伺服器忙」就用 |
| glaze | GPT：不取消「您說得完全正確！」 |
| retract | 陳經理：寫了釣魚信再刪掉 |
| astra | GPT：幾位客人直接用 Astra |

結束時印出一段 JSON：`out`（截圖資料夾）、`final`（最後的狀態）、`errors`（console 錯誤或警告、頁面錯誤、載入失敗的檔案、字型沒載入、簡體模式下沒轉換的字）、`log`（每一步做了什麼）。`errors` 不是空的話，指令以失敗結束。

截圖照順序編號，例如 `05_d1_aming1_start.png`、`06_d1_aming1_reply.png`，可以一張張看畫面有沒有跑版。

## 版面檢查：`node tools/layout_check.mjs`

在瀏覽器裡把畫面實際排出來，量有沒有文字被擠出框外：

- 客人畫面：每位客人分別用 Claude、GPT 和「被叫錯名字的 DeepSeek」各開一次，檢查客人的訊息、需求清單、稱呼說明有沒有超出框。
- 早上的日報：九個模型各玩 `--runs` 局（預設 12 局，共 540 個早上），檢查左右兩欄有沒有超出。

有任何溢出就以失敗結束，並列出是哪位客人、哪一局哪一天。也可以加 `--url`、`--browser`。加 `--lang=cn` 改排簡體版，同時檢查每個畫面有沒有沒轉成簡體的字；繁簡兩種都要跑。

預設用 800×450（橫式的原尺寸）。其他螢幕：

- `--portrait`：手機直拿（390×664、觸控）。
- `--size=寬x高`：指定視窗大小；觸控裝置加 `--touch`（手機橫拿的精簡版面只在觸控裝置出現）。

用這兩個參數時，除了上面的檢查，還會檢查：每位客人的畫面沒有東西超出畫面左右、可以捲動的框沒有橫向溢出、工具列沒有被擠出畫面、桌面至少還有 100px 高（結果裡有「桌面高度」的最小、中位數、最大）、直式的頂欄只有兩排；日報沒有超出畫面；另外把所有畫面和視窗各開一次（標題、九個模型的選擇畫面、手冊、抽屜、回標題確認、地區檢查、搜尋結果、文件、回覆單、交付結果、找外援、Astra、生成的圖、下班結算、新工具、寫進抽屜、這週結束、被換掉、更新紀錄、成就的稱號和結局），檢查沒有超出畫面、沒有漏轉簡體。改到畫面時，建議至少再跑 `--portrait`、`--portrait --lang=cn`，以及幾種不同比例的 `--size`（例如 `--size=869x360 --touch`、`--size=375x553 --touch`、`--size=768x1024 --touch`、`--size=1850x957`）。

## 公開網頁檢查：`node tools/pages_check.mjs`

確認只靠倉庫裡的檔案，網頁版就能正常玩（GitHub Pages 這類靜態網站）：

1. 直接從 git 取出已提交的檔案（預設 `HEAD`，可以用 `--ref` 指定），不讀工作資料夾裡沒提交的東西。
2. 在本機開一個網站，放在 `/prompts-please/` 子路徑底下（和 GitHub Pages 的網址結構一樣；可以用 `--base` 改），檔名大小寫要完全一致才找得到。
3. 用自動試玩跑四局（Claude 正常、DeepSeek 困難、GPT 故意踩陷阱，以及 Seed 用簡體中文正常玩）。
4. 手機橫拿（844×390、觸控）：檢查字型、頭像、開局、工具卡「點一下看說明、再點一下才使用」；再模擬一次雙指放大，確認放大倍數不會被遊戲重算（無頭瀏覽器不一定真的放大，結果裡的 `zoom` 是實際的放大倍數，iPhone 的實際行為要用手機確認）。
5. 手機直拿（390×664、觸控、iPhone 的瀏覽器標識）：確認是直式版面，用點擊實際走過一單：開局、工具卡點兩下、打開文件、交付、看到結算，畫面不能有橫向溢出。
6. 電腦五種視窗（1296×645、1920×1080 的 125% 和 150%、1850×957、2490×1293）：放大倍數要符合規則（填滿；和整數倍差不到 10% 時用整數倍），結果會列出舞台大小、字的大小、佔視窗的比例。

失敗的條件：遊戲要了不存在的檔案（沒提交、路徑或大小寫不對）、自動試玩有錯誤、手機或電腦的檢查沒過。結果也會列出沒被用到的素材檔。

網站架好之後，可以用 `node tools/pages_check.mjs --url=<網址>` 直接檢查線上版。

公開或更新網頁版之前，建議依序跑：`npm test`、`node tools/layout_check.mjs`、`node tools/layout_check.mjs --lang=cn`、`node tools/layout_check.mjs --portrait`、`node tools/layout_check.mjs --portrait --lang=cn`、`node tools/pages_check.mjs`。

## 手動測試

- 網址加 `?seed=數字`：固定隨機結果，重現同一局。
- 網址加 `?dev=1`：標題頁多一個「開發工具」，可以選模型、難度、種子，直接跳到任何一天的任何一位客人；遊戲中右上角的「開發」可以重來這位客人、跳過、直接下班、加白米飯、調信任。開發模式不存檔。
- 網址加 `?lang=cn` 或 `?lang=tw`：直接用簡體或繁體開。
- 改了任何中文內容之後跑 `npm test`；新增的文字用 `npm run zh -- --show=<客人 id>` 看一次簡體版。
